# ドキュメント管理方針

## 目的

情報を置く場所を役割ごとに固定し、実装と説明の不一致、秘密情報の混入、資料の重複を防ぎます。

## 4層の役割

| 層 | 役割 | 保存する内容 |
| --- | --- | --- |
| GitHubリポジトリ | 技術情報の正本 | コード、設定の雛形、仕様、ADR、運用、復旧、変更履歴 |
| ルートREADME | ポートフォリオ | 課題、提供価値、主要機能、設計上の特徴、技術スタック、入口 |
| docs | 詳細技術資料 | 機能仕様、構成、認証、課金、データ、監視、公開、障害対応 |
| Notion | 企画・顧客視点のメモ | 顧客インタビュー、仮説、競合メモ、コピー案、初期ロードマップ |

Notionは現時点では必須ではありません。メモの量や共同編集の必要性が増えた時点で導入します。

## 正本へ昇格する条件

Notion上の内容が次のいずれかに該当した時点で、GitHubのIssueまたはdocsへ移します。

- 実装方法、API契約、データ構造を決めた
- 認証、課金、個人情報、利用規約に影響する
- 公開・監視・障害対応の手順になった
- 利用者へ提供中の機能説明になった
- 将来の担当者が復旧や変更に必要とする

Notionへのリンクだけを正本として残さず、決定内容そのものをGitHubへ記録します。

## 更新ルール

- コード変更で挙動が変わる場合は、同じPull Requestまたはコミットで関連資料を更新します。
- READMEは詳細を抱え込まず、docs内の正本へリンクします。
- 時点依存の値には確認日を添え、古くなった記述は削除または更新します。
- 未実装、試験中、公開停止中を明確に区別します。
- 同じ説明を複数ファイルへ複製せず、1つの正本へリンクします。
- ファイル名は英語の小文字とハイフン、本文は日本語を基本とします。

## 秘密情報

次の情報はGitHub、Issue、Pull Request、Notionへ保存しません。

- APIキー、OAuth client secret、Webhook secret
- 復号鍵、認証用ランダム値、運営登録コード
- 顧客の氏名、メール、LINE識別子、決済情報
- 本番データベースのダンプやログ原文

リポジトリには変数名、用途、ローテーション時の注意だけを記録します。値はCloudflareやGitHub Actionsなどの暗号化されたSecretへ保存し、復旧用の秘密情報は別の非公開保管先で管理します。

## レビュー観点

- 記載内容が現在のコード・設定・公開UIと一致する
- ローカルリンクが切れていない
- 秘密情報や利用者データが含まれない
- 利用者向け説明と運営向け手順が混在していない
- 廃止した機能、価格、モデルが現行として残っていない
